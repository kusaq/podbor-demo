# Backend автоподбора

Backend работает на Supabase PostgreSQL и Edge Function `api`. Таблицы закрыты для прямого доступа из браузера. Сервер получает пользователя из проверенной подписи Telegram или действующей десктопной сессии. Все методы используют существующий POST endpoint `/functions/v1/api`, JSON `{ action, payload, initData }` либо `{ action, payload, desktopSession }`. Секретный `service_role` остаётся на сервере.

## Методы подбора

| action | payload | Результат |
|---|---|---|
| `backend.settings.get` | `{}` | Общие настройки компании |
| `backend.settings.save` | `revision`, `dealer`, `pricing`, `exchange`, `valid_days`, `letterhead_id` | Новая версия настроек. Только владелец или админ |
| `backend.asset.save` | `name`, `content_type`, `data_url` | ID неизменяемого бланка, только владелец или админ |
| `backend.asset.get` | `id` | Бланк своей компании |
| `backend.request.get` | `request_id`, необязательный `page` | Варианты, серверная оценка цены, настройки и страница истории КП |
| `backend.option.save` | `request_id`, `title`, `description`, `scenario`, `currency`, `input`, `client_price`, `market_median`, `term`, `source_name`; для изменения ещё `id`, `version` | Вариант, рассчитанная сервером себестоимость и оценка возможности отправки |
| `backend.option.review` | `request_id`, `id`, `version`, `decision`, `note` | `requested` для запроса; `approved` и `rejected` доступны владельцу и админу |
| `backend.option.archive` | `request_id`, `id`, `version`, `archived` | Убранный или восстановленный вариант |
| `backend.offer.create` | `request_id`, массив `option_ids` | Новая неизменяемая версия КП |
| `backend.offer.get` | `id` | Точный снимок сохранённого КП |
| `backend.offer.sent` | `id` | Отметка ручной отправки и переход заявки в «Думает» |

Поля `input` содержат числовые значения `purchase`, `base_rate`, `logistics`, `duty`, `recycling`, `documents`, `commission`. Все суммы кроме `purchase` относятся к рублям. Для импорта `purchase` указывается в валюте закупки, `base_rate` в рублях за 1 единицу валюты. В сценарии `rf` закупка указывается в рублях, импортные статьи не включаются в итог. Отрицательные суммы не допускаются. Цена клиенту всегда в рублях.

`pricing` содержит `median_enabled`, `median_pct`, `margin_enabled`, `margin_pct`. `exchange` содержит `mode` со значением `percent`, `add` или `fixed` и числа `percent`, `add`, `fixed`. `dealer` содержит строки `name`, `inn`, `address`, `phone`.

## Ограничения и права

- Доступ к заявке определяется компанией и текущим ответственным. Создатель не сохраняет доступ после переназначения, если он менеджер.
- Архивная заявка доступна для чтения и скачивания сохранённых предложений. Новые варианты, решения и отметки отправки требуют возврата заявки из архива.
- В заявке до 100 сохранённых вариантов, в одном КП до 30 разных вариантов. История КП возвращается страницами по 20.
- Бланки PDF, PNG или JPEG до 2 МБ. Проверяются MIME, base64 и сигнатура файла. Старые бланки сохраняются для прежних версий КП.
- Браузер не задаёт автора, компанию, себестоимость, расчётный курс или статус согласования. Неизвестные поля метода отвергаются.
- SQL-проверки и аудит работают внутри одной транзакции. Нет `SECURITY DEFINER`, публичное исполнение функций запрещено.
- Подтверждение связано с финансовыми данными и действующими ценовыми правилами. Сохранение изменённого варианта снимает подтверждение. Ожидающее решения и отклонённое предложение нельзя отправить.
- Создание КП и отметка отправки проверяют реальные варианты. Снимок старой версии остаётся доступен для просмотра, но после изменения цены требуется новая версия для отправки.
- Сведения об источнике не включаются в клиентский снимок. Телефоны, email, ники и ссылки в текстовых полях вариантов маскируются регулярными выражениями. Это не ИИ-анонимизация имён и не очистка фотографий.

## Хранение

`dealer_settings` содержит общую конфигурацию. `dealer_assets` хранит бланки. `request_options` содержит варианты и снимки расчётов. `price_decisions` сохраняет историю решений. `request_offers` хранит версии КП, а `dealer_events` и существующая `crm_activity` содержат аудит.

Схемы применяются после `schema.sql`, `workspace.sql`, `crm.sql`. Существующее персональное демохранилище сохраняется для совместимости. Секреты, настройки Supabase Auth и токен бота для этого обновления не меняются.

## Проверка

`npm test` проверяет вход и контракты API. `npm run test:domain` проверяет цепочку через браузер с имитацией API и пользователей. `tests/domain-database.sql` проверяет реальные SQL-функции на временных данных и завершает транзакцию откатом. Перед запуском этого SQL требуется применить доменную схему.

Тесты охватывают расчёт РФ и импорта, запрет цены ниже себестоимости, запрет самоодобрения менеджером, устаревшие версии, сброс согласования, неизменяемость КП, повторную отметку отправки, изменение правил компании и изоляцию доступа.
