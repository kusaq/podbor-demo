# Подбор

Интерактивный прототип Telegram Mini App для автоподбора. Дизайн Bond и палитра Meridian Blue сохранены. Основной файл приложения `index.html`, генератор PDF `pdf.js`, серверная функция `supabase/functions/api/index.ts`.

## Что работает

- Вход по подписи Telegram и управление доступами по Telegram ID через Supabase.
- Просмотр кабинетов менеджера, владельца и поставщика из аккаунта администратора. Переключение кабинета не меняет серверную роль.
- Создание запросов с анкетой, проверка дублей по нормализованному телефону и отметка согласия клиента.
- Поиск запросов, статусы клиента, несколько причин отказа и обязательный комментарий для «Другое».
- Демонстрационный подбор Camry, сравнение, обзвон, расчёт цены и подтверждение цены в рамках сценария.
- Копирование предложения, загрузка PDF/PNG/JPEG-бланка, генерация PDF с кириллицей, неизменяемые снимки версий КП и их повторное скачивание.
- Персональное сохранение рабочего состояния в Supabase. Повторный вход на другом устройстве загружает состояние того же аккаунта.
- Проверка версии при сохранении. Конфликт между устройствами не перезаписывает серверные данные. Перед явной загрузкой серверной копии сохраняется локальная резервная копия.

## Границы прототипа

Это ещё не многопользовательский MVP дилера. Рабочие пространства привязаны к отдельным Telegram ID. Совместная работа менеджера и владельца с общими запросами, изоляция компаний и передача запросов между сотрудниками ещё не реализованы. Проверка роли и активности пользователя выполняется сервером при каждом обращении.

Пример Camry содержит демонстрационные варианты, рынок и историю. Для новых запросов реальные результаты поиска не подставляются. МойСклад, CRM API, сервис объявлений, ИИ-разбор, голосовое распознавание и отправка сообщений поставщикам не подключены. Смена статуса и сохранение версий не отправляют сообщения клиентам.

История цен, подтверждения и демонстрационные настройки в персональном рабочем пространстве не являются серверным финансовым workflow. Для полноценного MVP потребуются отдельные сущности компаний, запросов, вариантов, решений владельца и аудит на сервере.

Вне Telegram используется браузерное демо, оно не получает доступ к серверным данным. Его локальное состояние отделено от состояния Telegram-аккаунтов. Новая версия PDF сохраняется по кнопке «Версия», загрузка PDF сама по себе не означает отправку клиенту. Бланк должен иметь свободную центральную область, для PDF используется первая страница. Фотографий автомобилей в демо нет.

## База и функция

В существующем проекте Supabase используются `app_users` и `mocks` из `supabase/schema.sql`. Персональное хранение добавляет `supabase/workspace.sql`. Обе схемы сохраняются в репозитории. Все таблицы закрыты для `anon` и `authenticated`, доступ к рабочим пространствам проходит через функцию с проверкой Telegram. Секреты не входят в репозиторий.

`workspace.get` и `workspace.save` всегда выбирают `user_id` из проверенного `initData`, а не из тела запроса. Для записи обязателен текущий `revision`. При конфликте сервер отвечает HTTP 409. Максимальный размер состояния ограничен сервером и базой.

## Проверки

Нужен Node.js 24 или новее.

```sh
npm test
npm ci
npx playwright install chromium --only-shell
npm run test:browser
```

Браузерный тест запускает временный HTTP-сервер, имитирует Telegram и ответы Supabase, проверяет два устройства и отдельный аккаунт, загружает бланк и скачивает PDF. Рабочих ботов, пользовательские аккаунты и production-данные тест не использует. Сервер и браузер завершаются автоматически.

## Публикация

Статический фронт публикуется GitHub Pages из `main`. Вместе с `index.html` необходимы `pdf.js` и каталог `assets`. Серверная функция развёртывается отдельно в Supabase. Деплой фронта не применяет SQL и не обновляет Edge Function автоматически.

Внешние библиотеки включены локально с закреплёнными версиями. PDF создаётся на устройстве, содержимое КП не передаётся стороннему PDF-сервису. Источники и лицензии перечислены в `assets/THIRD_PARTY.md`.
